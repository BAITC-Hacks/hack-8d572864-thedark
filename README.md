**Поток данных:**
1. Пользователь загружает документ «до» и документ «после» (или использует
   встроенные тестовые примеры).
2. `core/parser.py` извлекает текст, сохраняя нумерацию пунктов (1.1, 2.3.4 и т.д.) —
   она нужна модели, чтобы указывать точный источник каждого вывода.
3. `core/analyzer.py` отправляет оба текста в Claude одним запросом со строгим
   системным промптом, который требует:
   - определить реорганизованные / сохранённые / созданные подразделения;
   - сопоставить функционал и найти потери функций;
   - найти дублирование функций и потенциальный конфликт интересов;
   - для каждого вывода указать источник (документ + номер пункта);
   - не делать выводов, не подтверждённых текстом.
4. Ответ модели в формате JSON парсится и отображается в `app.py`: таблицы,
   раскрывающиеся карточки с источниками, итоговое заключение.

## Установка и запуск

```bash
# 1. Клонировать репозиторий и перейти в папку
git clone <ссылка на репозиторий>
cd mvp

# 2. Создать виртуальное окружение (рекомендуется)
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Указать ключ Anthropic API
cp .env.example .env
# откройте .env и вставьте свой ключ, затем экспортируйте:
export ANTHROPIC_API_KEY=sk-ant-...     # Windows (PowerShell): $env:ANTHROPIC_API_KEY="sk-ant-..."

# 5. Запустить приложение
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`. По умолчанию включены
встроенные тестовые примеры — просто нажмите **«Запустить анализ»**, чтобы
увидеть результат без загрузки своих файлов.

## Тестовый сценарий (для проверки)

В `data/` лежат два сокращённых варианта реального Положения о внутреннем
аудите — редакция №8 («до») и редакция №9 («после»). Между ними заведомо
известны изменения:
- в редакции №9 появились два новых департамента — **ДИТААД** и **ДОА**,
  которых не было в редакции №8 (там была обобщённая роль «Директор
  направления внутреннего аудита»);
- часть функций и пунктов раздела 5 переформулирована и перераспределена
  между новыми департаментами.

Агент должен отметить ДИТААД и ДОА как «созданные», ДНМ и ДККМ — как
«сохранённые», и указать конкретные пункты (например п. 3.4, п. 5.3.2) как
источник каждого вывода.

## Известные ограничения MVP и возможное развитие

- Сравнение выполняется **одним запросом к модели** — для более надёжной и
  проверяемой работы на больших комплектах документов стоит разбить на
  отдельные шаги (агентный pipeline): (1) извлечение структуры каждого
  документа отдельно → (2) сопоставление → (3) верификация ссылок на пункты
  отдельным проверочным вызовом.
- Нет автоматического сопоставления с внешними НПА/стандартами и
  бенчмаркинга с другими операторами (см. раздел «Опционально» задачи) —
  следующий шаг развития.
- Для очень больших документов (сотни страниц) потребуется чанкинг и
  векторный поиск (RAG) вместо передачи полного текста в промпт.
- Выводы ИИ носят рекомендательный характер и требуют проверки ответственным
  сотрудником (см. раздел «Ограничения» задачи).
